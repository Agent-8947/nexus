# 🏆 Golden Standard: Spec-Driven Zero-Stub Paradigm

Этот воркфлоу жестко фиксирует новую парадигму архитектуры NEXUS, исключающую фантазии агентов, модули-пустышки (stubs) и оторванный от среды код. Любой агент, реализующий новый продукт или модуль, **обязан** следовать этому стандарту.

## 🔴 КРИТИЧЕСКОЕ ОГРАНИЧЕНИЕ (Zero-Stub Tolerance)
АГЕНТАМ КАТЕГОРИЧЕСКИ ЗАПРЕЩАЕТСЯ:
1. Создавать "заглушки" кода (вида `def run(): pass` или `// TODO: implement logic`).
2. Генерировать структуру файлов и имена "из головы" — они обязаны соответствовать метрикам реальных репозиториев WIKI.
3. "Хардкодить" вызовы внешних файлов в CLI. Оркестраторы должны быть динамическими.

## 🟢 Обязательный Пайплайн (3 Фазы)

**Phase 1: Глубокий Анализ (Extraction & Spec Generation)**
Прежде чем писать код, агент обязан выкачивать данные из мировых аналогов (через GitHub API или `gh api`). С помощью AST-анализа извлекаются реальные импорты, API-адреса и логические цепочки. Результат сохраняется в `*.spec.json`. 

**Phase 2: Синтез (High-Fidelity Construction)**
На базе вытянутых спецификаций генерируется боевой код. Он должен содержать в метакомментариях сигнатуры реальных OpenSource-библиотек (например, SpiderFoot, Crawl4AI и т.п.), и быть 100% исполнимым (Exit Code 0).

**Phase 3: Динамическая Оркестровка**
Сгенерированная экосистема модулей всегда накрывается **динамическим оркестратором** (по аналогии с Metasploit). 
- Главный CLI сканирует папку (через `importlib` или аналоги).
- Подтягивает все корректные инструменты.
- Прогоняет цель автономно по каждому модулю и аккумулирует вывод в единый JSON/отчёт.
