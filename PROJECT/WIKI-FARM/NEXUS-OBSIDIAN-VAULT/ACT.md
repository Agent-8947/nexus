# ACT — Локальный Запуск GitHub Actions через Docker

## Описание
Инновационный инструмент, позволяющий запускать рабочие процессы (.github/workflows/) из GitHub Actions на локальной машине. `act` считывает YAML-файлы ворклоу, использует Docker-контейнеры для создания идентичной серверной среды и выполняет все шаги сборки, тестирования и деплоя локально. Девиз проекта: "Think globally, act locally".

## Основные Разделы
1. **GitHub Actions Runner** — эмуляция окружения виртуальных машин GitHub.
2. **Docker Integration** — автоматическое подтягивание и сборка необходимых образов для экшенов.
3. **Local Task Runner** — использование `act` как замены `Makefile` для автоматизации локальных задач.
4. **Environment Match** — полная конфигурация переменных окружения и файловой системы под стандарты GitHub.
5. **VS Code Extension** — плагин для управления ворклоу прямо из редактора.

## Почему это Killer-App
- **Fast Feedback Loop** — не нужно пушить и ждать CI/CD в облаке, чтобы проверить опечатку в скрипте.
- **Offline Reliability** — возможность тестирования пайплайнов без доступа к интернету (после загрузки образов).
- **Cost Saving** — экономия минут GitHub Actions (особенно на приватных репозиториях).

## Архитектурная Ценность для NEXUS
- **Паттерн:** Local CI/CD Agent — NEXUS-агент может использовать `act` для автоматической проверки работоспособности синтезированного кода.
- **Интеграция:** NEXUS Orchestrator интегрирует `act` для валидации новых "чертежей" (DNA templates) перед их фиксацией.
- **Ключевое:** Использование `act` как универсального исполнителя задач (task runner) позволяет унифицировать локальную и серверную автоматизацию NEXUS.

## Пример использования
```bash
# Запуск всех экшенов для события push
act push

# Запуск конкретной джобы из конкретного ворклоу
act -j build -W .github/workflows/main.yml

# Просмотр списка доступных действий
act -l
```
